# ÇevirmenX project instructions

## Repository delivery standards

- For new public projects, include a useful README, a license file (MIT when the owner requests MIT), .gitignore, changelog, and relevant setup/build/release instructions. Preserve an existing license unless the owner authorizes changing it.
- For releases, keep website, manifest, package metadata, release notes, and store packages on the same version. Check for stale version labels.
- Use one accessible language dropdown with native language names; do not place seven language-code buttons in a row. Support RTL for Arabic.
- Integrate related tools into the main application navigation instead of adding disconnected footer links.
- Verify significant UI changes at 390px and 768px and exercise primary interactions. Clearly report checks that use mocks versus real browser-extension APIs.
- Do not describe a release as flawless or fully verified unless evidence supports that claim.
